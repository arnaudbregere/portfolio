## 3. La CI découpée en cinq jobs (PR #45, commit `64ab9b0`)

Demande d'Arnaud : renommer « Tests de bout en bout » en « Tests e2e », et
séparer les vérifications.

Un seul job faisait tout. Désormais cinq jobs parallèles : `lint` / Lint,
`types` / Types, `unit` / Tests unitaires, `build` / Build, `e2e` / Tests e2e.
L'installation commune est extraite dans une action composite
`.github/actions/deps/action.yml` (`setup-node` sur `.nvmrc`, cache npm,
`npm ci`), paramétrée par `working-directory` pour servir la racine comme
`e2e/`.

Les checks requis de la protection de branche ont été migrés par `gh api`
**avant** le merge, pour que la PR ne reste pas bloquée sur un nom de check
qui n'existait plus.

## 4. La topologie d'hébergement, établie par la mesure

Arnaud affirmait que son site était hébergé chez **Hostinger** et non Vercel.
La mesure dit l'inverse :

- Hostinger est **registraire et DNS** du domaine `arnaud-bregere.fr`. Il ne
  sert aucune page.
- **Vercel** servait déjà l'ancien portfolio, via le projet `cv-nuxt4`.

Les enregistrements DNS pointaient sur Vercel ; c'est ce qui a permis le
basculement sans toucher à Hostinger.

## 6. La mise en production sur Vercel (issue #46)

Issue #46 créée pour le processus de livraison, et `.claude/skills/deploy/SKILL.md`
entièrement réécrit pour Vercel.

Étapes réalisées par Arnaud dans l'interface, guidé pas à pas :

1. Nouveau projet Vercel importé depuis le dépôt `portfolio`. Preset Nuxt
   auto-détecté, **aucune variable d'environnement à saisir** — les trois
   variables lues par `/api/health` sont fournies par Vercel au build.
2. Déploiement.
3. Les trois domaines (`arnaud-bregere.fr`, `www.arnaud-bregere.fr`,
   `cv-nuxt4.vercel.app`) **déplacés** de l'ancien projet `cv-nuxt4` vers le
   nouveau.

Deux obstacles rencontrés :

| Symptôme | Cause | Correction |
|---|---|---|
| La fenêtre « Add Domains » cochait par défaut « Redirect apex domains to www (recommended) ». | Réglage par défaut de Vercel, contraire au canonique du site : `runtimeConfig.public.siteUrl` est l'**apex**. | Case décochée avant validation. |
| Vercel refusait de faire rediriger `www` vers l'apex : `You have redirected another domain (cv-nuxt4.vercel.app) to this domain. In turn, you cannot redirect this one.` | Vercel interdit les chaînes de redirection. `cv-nuxt4.vercel.app` pointait sur `www`, qui aurait alors pointé sur l'apex. | Ordre imposé : d'abord recibler `cv-nuxt4.vercel.app` sur l'**apex** (fait, vérifié `308`), puis seulement `www` sur l'apex (**reste à faire**). |

### Pourquoi l'apex et pas `www`

`runtimeConfig.public.siteUrl` reste `https://arnaud-bregere.fr`, sans `www.`.
Changer la valeur pour `www.` cassait `tests/unit/site-link.spec.ts`
(`AssertionError: expected '_blank' to be undefined`) : `isExternalUrl`
compare les origines, donc un lien `www.` du site devenait un lien sortant.
Le remède est un réglage chez l'hébergeur, pas une ligne de code. Le compromis
est documenté dans `nuxt.config.ts` et dans l'issue #46.
